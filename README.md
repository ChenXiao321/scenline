# 场景流程原型平台

把《业务场景梳理》风格的 Markdown 文档变成**可浏览的结构化场景库 + 可播放的流程原型 + 可操作的工具原型**。

三层关系：场景文档（问题域）→ 目标工具（产品）→ 本平台（从场景生成工具原型 + 改规格反哺界面需求）。核心交付是**工具原型**：从场景描述长出目标工具的可点击界面，改规格 → 界面跟着变；流程播放器是辅助视图。

## 三个视图

- **场景详情**：结构化展示场景各小节（含「关键界面 / 交互」界面素材）。
- **▶ 流程原型**：泳道播放器（多流程段 tab、单步/自动播放/变速、点击行跳转）。
- **🛠 工具原型**：按界面规格渲染成可真正操作的界面（当前支持向导式：分步表单、必填/正则校验、实时预览、确认页、执行进度模拟、结果通知）。点「✎ 编辑规格」直接改 JSON，保存后界面立即按新规格渲染——**改规格就是这个平台的核心用法**。

### 界面规格格式（JSON，存于 `ui_spec` 表，重导文档不影响）

```jsonc
{
  "kind": "wizard",
  "title": "工具窗口标题",
  "desc": "副标题说明",
  "computed": [   // 由字段值拼接的派生值，preview=true 显示在右侧实时预览栏
    { "key": "repoName", "label": "仓库名", "template": "{project}_{p6}_{p5}{p4}", "preview": true }
  ],
  "screens": [    // 向导步骤
    { "id": "s1", "title": "步骤名", "desc": "说明", "flowSteps": "步骤 1-2",
      "fields": [
        { "key": "project", "label": "项目", "type": "select", "options": ["A", "B"], "default": "A", "required": true, "help": "灰色小字" },
        { "key": "p8", "label": "P8", "type": "text", "default": "100", "readonly": false,
          "validate": { "regex": "^...$", "message": "校验失败提示" } },
        { "key": "owner", "label": "负责人", "type": "role-picker" },          // 从当前工作域角色库选择
        { "label": "只读展示", "type": "display", "template": "{project}" },   // 或 "text": "静态文本"
        { "label": "派生值", "type": "computed", "computedKey": "repoName" }
      ]
    }
  ],
  "confirm": { "title": "确认创建", "note": "说明", "fields": ["repoName", "compiler"] },  // 汇总展示的 key（字段或 computed）
  "run": {
    "button": "确认创建",
    "stages": ["执行阶段 1", "执行阶段 2"],          // 逐条打勾的进度模拟
    "successTitle": "完成",
    "successFields": [{ "label": "地址", "template": "http://x/{repoName}" }],
    "actions": [{ "label": "打开", "primary": true, "toast": "提示文本" }, { "label": "重来", "reset": true }]
  }
}
```

模板占位符 `{key}` 可引用字段值或 computed 值。场景 1.1 的种子规格见 `specs/ui-spec-1.1.json`（已入库）。

### 场景编辑

侧栏「＋ 新建场景」或场景详情「✎ 编辑场景」打开场景编辑器：编号/标题/分组/业务价值、主要用户与不覆盖（角色库点选）、触发/前置条件、主流程与变体步骤表（步骤角色从角色库下拉、增删排序）、验收标准、异常分支、界面素材、待确认/待办，全部可编辑。

**平台编辑优先**：在平台保存过的场景（侧栏标「编」）与手工创建的场景（标「手」），重新导入文档时**不会被文档覆盖**，跳过并记入导入告警。删除导入来源的场景时需注意：下次重导会把它带回来，需同步删源文档。

### 平台是唯一事实源 → 文档只导出不手改

**自导出功能落地起，平台数据为场景的唯一权威来源，Markdown 文档不再手工编辑。** 工作方式：

1. 在平台里改场景/角色/拆解/界面规格；
2. 顶栏「⤓ 导出 MD」一键把当前库内容**重新生成**整份场景文档（`GET /api/workspaces/{id}/export/md`）；
3. 导出的文档带「⚠️ 本文件由平台导出，请勿手工编辑」水印，用于分享/存档/评审，**不要再手动改它**——要改请回平台改完重新导出。

导出会：按分组（domain）重建章节层级、角色定义表、各场景（业务价值/触发/前置/主流程表/变体/界面素材/验收/异常/流程图备注）+ 待确认小节；**步骤号统一输出为数字**；内容可被自家解析器无损读回（闭环已验证）。过程拆解（process_spec）与界面规格（ui_spec）不写入场景文档，走独立导出（PDF/HTML）。

> 原「回写式双向同步」因双权威源必冲突而放弃，改为本导出式单向同步。

### 角色定义

**点击侧栏的角色 chip**（含「系统」）在主区展开角色详情页：完整定义 + **涉及场景链路**（作为主要用户的场景标「主要用户」，流程步骤中出现的场景标步数，含分支变体），点场景卡可直接跳转。详情页内直接「✎ 编辑」「删除」；侧栏「＋ 新增」创建角色。角色库的用途：

- 场景步骤的泳道归属（导入时按角色名/简称自动识别）；
- 工具原型规格中的 `"type": "role-picker"` 字段 —— 界面上渲染成从角色库选人的下拉框。

重新导入文档时，文档角色表中**新出现**的角色自动补入；已有角色以面板内容为准，不会被文档覆盖（可放心在平台上维护）。

## 架构

- **平台层（通用）**：数据模型、Markdown 解析器（`backend/parser/scenario_doc.py`）、泳道播放器——不含任何具体业务词。
- **工作域层（每项目一个）**：角色库、场景树、待确认项。项目 = 工作域；第一个工作域「GPULSE 线上集成扩展」由《业务场景梳理-项目全新开发与历史复用.md》导入。

### 存储

**每个项目一个独立 SQLite 文件**，可单独备份/迁移/删除（删项目 = 删文件）：

```
data/
├── platform.db           # 项目注册表（id/名称/描述/源文档路径）
├── platform.db.bak       # 单库拆分前的备份（确认无误后可删）
└── projects/
    └── ws-<id>.db        # 每项目的角色/场景/ui_spec/process_spec/import_report
```

## 运行

```powershell
# 后端（首次：python -m venv .venv && pip install fastapi uvicorn pydantic）
.venv\Scripts\python.exe -m uvicorn main:app --app-dir backend --port 8000

# 前端（开发模式，另开窗口；生产模式 npm run build 后由后端直接托管）
cd frontend && npm install && npm run dev
```

打开 http://localhost:5173 （开发）或 http://localhost:8000 （已构建）。

## 项目管理

启动后进入**全局首页**：卡片墙列出所有项目（名称/描述/角色数/场景数/源文档/创建时间），点卡片进入对应项目，卡片右上角可删除项目；点顶栏 logo 随时返回首页。

顶栏「＋ 新建项目」三种起步方式：

- **导入场景文档**：指定一份符合下方编写约定的 Markdown 场景文档；
- **手动添加**：空项目，从「👥 角色定义」开始自己搭建；
- **从模板创建**：生成一份含全部约定结构的最小示例文档（存于 `data/docs/<项目名>.md`）并导入，在此基础上修改。

「🗑 删除项目」删除当前项目及其角色、场景、界面规格（有确认框）。「↻ 重新导入」从绑定的源文档重新解析（角色只增不覆盖，界面规格不受影响）。

也可以直接用接口创建：

```powershell
$body = @{ name = "项目名"; path = "D:\path\to\场景文档.md" } | ConvertTo-Json
Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/workspaces/import" -Method Post -Body ([Text.Encoding]::UTF8.GetBytes($body)) -ContentType "application/json"
```

## 文档编写约定（解析器识别的结构）

- `## 一、角色定义` 下的角色表（角色 / 英文简称 / 核心工作 / 权限特点）
- `#### 场景 X.Y：标题` —— 场景标题；`#### 场景 X.Y 待确认 / 待办` —— 挂到场景 X.Y 的开放问题
- 场景体内：`**主要用户**`、`**触发条件**`、`**前置条件**`、`**主流程**`（`| 步骤 | 用户操作 | 系统响应 |` 表，用户操作为 `-` 的行归「系统」）、`**验收标准**`、`**异常分支**` 表、`**关键界面 / 交互**`（界面素材列表，保留缩进层级）
- `##### 分支 A：…` —— 场景内的并行路径，作为独立流程段参与播放

## 已知边界

- 步骤的角色归属：自动识别角色名/简称，识别不了时暂归第一主要用户并记录到导入告警（工作域详情 `warnings` 字段）；多角色场景的细粒度归属待切片 3 的编辑能力解决。
- 状态面板（仓库/分支/FC 状态随步骤变化）尚未实现，当前为文本级泳道播放。
